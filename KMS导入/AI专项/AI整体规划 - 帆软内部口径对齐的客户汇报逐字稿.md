# 帆软内部的AI转型

作为引子，如果客户对AI的了解程度不深可以讲一讲，能够和客户在 AI 转型初期的痛点产生共鸣，从而让客户进入状态。

但如果客户对 AI 的了解非常深入，并且已经做过非常多的落地实践过了出奇的迷茫期，或者客户只想了解帆软能够给他提供什么对帆软本身的内部 AI 转型并不怎么感兴趣的话，这部分就可以不讲了。

我们公司是从 2024 年开始往 AI 方向展开探索的。但其实在 2024 年，公司里只有不到十个人在做 AI 相关的研发，推出的第一个产品叫 ChatBI

在2025年年初，公司准备大力向 AI 转型，全面拥抱 AI的时候，我们遇到的第一个现实问题就是“无人可用”。

身边没有懂 AI 的人，大家还在软件时代。要做 AI，首先得懂 AI，但原本做软件、做 SaaS 的人，怎么变成做 AI 的人呢？

临时去社会上招聘肯定不好招，也招不到。

所以帆软在做 AI 转型时，首先想的是如何从内部把 AI 的氛围构建起来，把内部的AI人才挖掘出来。由此我们诞生了三个活动。
## AI脉冲计划

这个计划很好解释，一句话概括就是：你花钱，我买单。

公司内部所有人，不论岗位，只要你愿意去购买并使用 AI 产品，并在用完后分享一段简短的心得

f比如在交流群里说明你用了什么产品、它帮你解决了什么问题、给你的工作和生活带来了什么改变

公司就给你报销。通过这个活动，公司内部有 600 多人参与围观，100多人购买使用了 AI 产品，让大家对 AI 有了一个初步的感受。
## 一杯奶茶带来的内部提效

通过第一阶段，大家基本上知道了 AI 能够改变哪些事情，以及能帮我们做什么。

我们第二个活动，其实就是希望大家在了解 AI 以后，用这种思维方式去审视企业里的工作，看看有哪些环节可以被 AI 改变。

所以我们发起了这个活动，要求如下：

你可以提出工作中哪一个环节、什么场景可以用 AI 来处理。

只要你提了需求，我就发给你一杯 30 块钱的奶茶券。

通过这个活动，我们发出去 100多个奶茶券，收集到了 100多个需求，形成了我们的企业内部需求池。和公司信息化部门配合，通过这个需求池，我们也真的让 AI 在企业内落地了一些实际场景。

**行政助手**

我可以演示一下，比如我们接到很多同学提的需求，反映现在的流程太麻烦：

1. 出差申请和报销录入太麻烦

2. 请假流程太麻烦

3. 预约会议室太麻烦

4. 在企业知识库里查找文档太麻烦，经常查不出来

这些都是同学们反馈非常多的问题。针对这些痛点，我们做了一个“行政助手”。

它具体有什么效果呢？我可以给大家演示一下。

企业微信搜：软妹，展示真实效果

**HR助手**

再比如说，我们的人事同学提到，以前找简历的过程非常麻烦。他可能一天里有一半的时间都在筛选简历，找到合适的之后，还要给对方打电话邀约面试。

针对这个痛点，我们做了一个 AI 简历助手。它能节省人事一半的筛选时间：

1. AI 会去各大网站爬取各种各样的简历

2. 将简历抓取回来后，直接与我们的 JD（职位描述）进行比对

这不再是以前那种简单的条件匹配（比如是否是一本学生、工作经验满几年等），它是真的能做到看完并理解每一份简历，再与 JD 进行深度匹配，最后给出一个匹配相似度。

## 黑客马拉松

再然后，我们开始真的对产品动刀了。我们发起了 AI 黑客马拉松计划，希望大家基于我们的产品和客户真实的需求，由前后方组队，使用 AI 方案去解决客户明确的需求。

具体的奖励规则如下：
1. 只要是使用 AI 解决的客户需求，且能够有一家及以上的客户去使用，我们就会给这个团队奖励 10 万元。
2. 我们设置了总计 100 万元的奖金池，来鼓励大家通过 AI 解决客户的问题，动手去真做。

目前公司已经有 40 多支队伍报名，有十几支队伍完成了初步的路演。我们也在这场 AI 黑客马拉松的项目中，看到了很多有价值的需求被解决，同时也看到了更多的 AI 相关人才涌现了出来。

以上就是帆软 AI 内部转型的一些实践。

通过这三个活动，我们：
1. 激发了大家对于 AI 的热情
2. 让大家进行了初步在 AI 落地方面的练习和实践
3. 识别出了内部对 AI 业务有潜力的种子选手，并吸收到了我们后续的任务和计划当中

# 帆软的AI战略

这部分作为承上启下的章节。重点讲：可定制的培训和个性化的实施，让客户知道我们什么都可以接。

标准的 AI 产品部分，因为它单独就有很多内容，放在下一节的时候再讲。

如果客户问到帆软做BI的，为什么要做AI可以讲：

帆软的 AI 战略分为三大块：
1.  AI 数字人才
2. AI 新产品与新功能
3. AI FDE工程师

那这三个战略分别是什么？为哪类客户解决什么问题？接下来在这一章节向各位领导和老师介绍一下。
## AI数字人才：个性化的培训服务 - luke

AI 数字人才其实就是针对那些处在AI转型相对初期位置的客户。还不太清楚 AI 的能力边界，AI能够帮自己做什么。同时对于内部需求痛点的提炼也不是特别明确。

那我们就提供 AI 数字人才服务。为客户进行培训，让客户知道如何进行 AI 转型，以及 AI 究竟能解决什么问题。

AI 数字人才服务具体包含以下内容：

- 通过数字人才专业的讲师，讲解 AI 专业知识和外部其他企业的最佳实践案例
- 帮助企业举办内部的沙龙讨论，策划脑暴活动
- 与客户现场共创沙盒演练，手搓 AI demo，验证 AI 是否真的能够解决需求

总之，就是将“AI 能做什么”带给客户，帮客户发掘自己有哪些痛点可以被 AI 解决，从而助力企业的 AI 转型变革。

这一部分是帆软资源重金投入的部分，一定要快速开发出来 AI 新产品、AI Native 的新产品。才能在下一个时代继续领先。

## FDE：AI前线开发工程师 - Thomas.shen*

FDE 所面对的客户，是那些已经对 AI 非常了解了，同时对于自己内部的需求也非常清晰，明确知道自身企业希望用 AI 解决什么问题。

不过部分或全部需求没有落在帆软能够提供的标准AI产品的能力范围之内。那这个时候帆软依然能够承接客户的需求。通过FDE工程师入场，进行现场开发，解决客户通用AI产品无法满足需求。

FDE不是卖标准产品的，而是与客户合作高定解决方案，填补客户需求与标准AI产品之间“最后一公里”的空白，确保AI技术真正转化为客户的生产力。

- 研发驻场现场开发
- **人天计费使命必达**

帆软为什么要做这个事情呢？这个事情人力劳动密集型重实施，其实并不是单纯为了赚这个实施的钱。

因为整个世界其实都处在 AI 转型落地的初期，这个时候的产品是非常匮乏的。有大量的产品都在开发的路上，或者还在 PPT 上。

所以大概率会出现客户的需求已经出现了，但是市场上还没有产品 Ready。那这个时候，我们仍然是希望服务好我们的客户，特别是战略客户和头部客户。

那通过 FDE 这种模式，可以让我们承接客户的需求。

标准的产品，用一个产品服务于 1 万个客户、10 万个客户，这种产品的开发周期是很漫长的，我们需要时间准备。

但是，如果我们只服务于一个客户，贴着客户的需求走，和客户一起共创，只考虑满足好一个客户的需求，在这种情况下，帆软是绝对有实力能够很好地满足我们的客户的。

这种模式对于帆软来讲另一个好处，那就是可以接收一线头部客户的需求，然后沉淀为帆软未来孵化标准品的一个需求池。

所以这是一个共赢的机制。在 AI 时代的初期：

- 我们的客户能在 AI 转型初期、市面上产品比较匮乏的时候，通过 FDE 的服务走在时代的前沿，能够快速地引入 AI 落地，覆盖企业的各种场景，降本增效，来提升企业的 AI 含量。
- 帆软也能够通过提供 FDE 服务来锁定一批客户、锁定一批需求。

## 企业级Agent（数字员工）构建平台 - ZIV代管后续授权

讲完上面的这些东西以后，客户很容易产生的一个问题是：“你们这么多的 agent （数字员工）是怎么做出来的？”

或者说，如果客户不问，我们也可以主动引导：我们公司未来会提供越来越多的 agent，除了目前这些之外，可能还会有几十、上百个agent。

那么，我们这么多的 agent 到底是怎么做出来的呢？经过我们的研究，其实市面上主流的 agent 生产方式无非以下几种：

**1. 使用工作流平台（如 Dify、Coze 等）**这种方式是通过 workflow 的形式把一个 agent 编排出来。

- 它的优点是上手成本低，通过界面上的“拖拉拽”和配置方式，就能快速搭建出一个 agent。
- 它的缺点是灵活性不足。因为它本质上仍然是 workflow 形式，面临的是有限节点，只能处理有限的分叉。
- 如果一个问题非常复杂，有很多分叉节点和链路，那么整个 agent 的设计将会变得异常繁琐。万一其中有某些考虑不周全的情况，我们的 agent 遇到后就只能尴尬地报错，无法处理。表现的不够智能。

以上就是通过 workflow 编排 agent 的一些优缺点。

**2. 其实就是传统的代码开发方式**

- 开发流程：通过产品经理定义需求，明确约束 agent 的效果和工作边界。研发人员则通过代码开发，使用 LangChain、LangGraph 或者其他 agent 框架，并结合 workflow（工作流）架构。
-  核心优势：这种方式既能保证效果稳定，又能确保 agent 足够灵活，能够处理客户的多种问题。我们之前介绍的很多 agent 都是通过这种方式开发出来的，旨在为客户提供表现稳定、同时又足够发散和智能的 agent。
- 存在的问题：这种开发方式消耗的产品和研发资源非常多，且开发周期通常较长。

**3. 第三种开发方式其实就是自主规划式的 Agent 开发。**在以前我们很难解释这个东西，但现在的好处是我们有了 OpenClaw。**你可以理解为，第三种开发方式就是 Openlaw。**

- 通过与 OpenClaw 的交互，它可以派生出一个又一个的实例 Agent。比如：
   (a) 你向 OpenClaw 讲述需求，让它制作一个通过打电话提醒重要事项的 Agent；
   (b) 你告诉它希望总结知识库里的哪几篇文档，它就会为你做一个知识问答和知识总结的 Agent。
- 核心理念与产品起源
   它的核心理念源自 Anthropic 公司的 Claude Code。这种理念是由 Code Agent 的工作方式泛化而来的，OpenClaw 是这种理念下的第一个具象化产品。
- 开源产品的潜在风险，虽然这种产品火了，看起来很先进，但也存在风险。因为它是一个开源产品。我们公司的研发和产品团队在研究过程中发现，这个产品的稳定性和安全性是有很大问题的：
   (a) 因为是开源，没有人会为产品兜底，使用它完全是用户的个人选择；
   (b) 如果今后出现任何问题（比如误删公司邮件或数据服务器），责任需要由使用者自己承担。
- 我们公司的解决方案。其实我们公司在 2025 年 12 月就开始开发类似的平台了。借助 Anthropic 的理念，我们确实在短短一个月左右就推进出了平台雏形。但此后我们花了大量时间去解决核心问题：
   (a) 平台的稳健性与安全性；
   (b) 接入企业各类信息系统后的适应性；
   (c) 确保将平台卖给客户后，保证使用效果。

## 多Agent（数字员工）接入与运维平台 - ZiV代管后续授权

在第一章节向客户介绍，帆软目前提供了七个 agent（数字员工），未来我们会提供越来越多的Agent（数字员工）。

在第二章节向客户介绍，帆软提供了一个 agent 的构建平台，将产生 agent 的能力赋能给企业，让企业自己去构建 agent。

我们继续向下推演。未来会出现一个什么样的局面呢？

**未来一定是一个Agent（数字员工）和人类员工协作的世界。**

企业里数字员工的数量会远远大于人类员工。可能一个企业只有 500 个人，但数字员工的数量会达到 2000 个，它们帮助人类员工完成各种各样的工作，处理繁杂事务，分析各种数据，从而形成人和智能体交叉协作的工作环境。

当这一天发生的时候，甚至不需要等到这一天，只要一个企业里有七八个或者十几个 agent，就会出现一些问题。

这个最后一章，核心不是“再介绍一个平台”，而是要把客户脑子里的未来画面推到一个必然结论：

**当企业里 Agent（数字员工）数量变多以后，问题就不再是“能不能做出 Agent”，而是“怎么让这么多 Agent 安全、稳定、低成本地长期运行，并且真正和人协作起来”。**

不然前两章讲完，很容易被客户理解成：
“你们已经有一堆 Agent 了，也有Agent构建平台了，那不就完了吗？”

但其实远远没完。
**单个 Agent 是点状价值，多 Agent 协作才会进入系统性复杂度。才能满足更大的客户价值。**
这时候企业需要的，就不是某一个 Agent，而是一个**多 Agent 接入与运维平台**。

我们预判企业会面临以下几个挑战：

**1. 系统接入越来越多，IT 维护压力越来越大：**每个 Agent 都要接 CRM、ERP、OA、BI、知识库、企业微信等系统。如果每做一个 Agent 就单独接一遍、维护一遍，IT 成本会迅速失控。所以企业需要统一的系统接入底座，实现一次接入、多 Agent 复用，减少重复建设和后续维护量。

**2. Agent 各自为战，缺乏统一上下文：**一个 Agent 知道客户刚开完会，另一个却不知道；一个知道项目背景，另一个又要重新问一遍。没有统一的上下文和记忆系统，Agent 就会反复“失忆”，人也要不断重复沟通。所以企业需要统一的上下文共享机制，让 Agent 更懂企业，也更懂人。

**3. 权限和安全边界会越来越复杂：**数字员工和人类员工一样，也需要身份、角色、权限和边界。它能看什么数据、调什么系统、做到什么程度，都必须被统一管理。否则，轻则效果差，重则带来真实的安全和合规风险。

**4. Agent 数量一多，稳定性和质量很难保障：**单个 demo 看起来很好，不代表规模化后还能稳定可用。企业会关心：哪些 Agent 经常失败、哪里出错、效果是否稳定、出了问题怎么追踪。所以必须有统一的监控、评测、发布和运维机制。

**5. 多 Agent 协作会成为常态：**未来完成一个复杂任务，往往不是靠一个 Agent，而是多个 Agent 分工协作。如果没有统一调度和协同机制，就会重复取数、信息冲突、任务断链。所以平台需要支持多 Agent 之间的分工、流转和汇总。

**6. 入口太分散，员工最终还是不愿意用：**如果每个 Agent 都有自己的入口、自己的交互方式，员工的学习成本会越来越高。最后不是效率提升，而是新的复杂度。所以企业需要统一入口、统一工作台、统一消息与任务中心，真正降低使用门槛。

所以

当企业里只有 1 个 Agent 的时候，问题还只是“这个 Agent 好不好用”；

当企业里有 10 个、50 个、100 个 Agent 的时候，问题就会变成“这些 Agent 怎么接系统、怎么管权限、怎么共享上下文、怎么协同工作、怎么统一运维”。

所以未来企业需要的，不只是一个个能干活的数字员工，更需要一套支撑数字员工规模化落地的基础设施。

而帆软会提供一个以帆软数据产品为核心底座的Agent接入、管理、运维平台。

这套平台的价值，不在于替代某一个 Agent，而在于让所有 Agent 可以被统一接入、统一治理、统一协同、统一运维，让数字员工真正成为企业长期可控、可复制、可沉淀的新生产力。

企业未来需要的，不只是软件系统，而是一套“人类员工 + 数字员工”共同工作的组织级操作系统。

谁先建立起这套多 Agent 的接入、治理、协同与运维体系，谁就更有机会率先进入真正的人机协作时代。
