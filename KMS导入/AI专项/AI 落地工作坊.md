# 核心判断

**相比于25年突然席卷的AI场景化浪潮，大量企业在25年还是观望和学习。**

**经过25年的市场教育，客户逐渐冷静，并且开始聚焦于AI真的能落地的场景，同时已经有大量客户在26年的信息化预算中，做了AI场景化的预算。**

但我们知道，目前的AI产品有一个死穴：**越通用，越没用**。 所以我们的AI产品，必须必须聚焦、必须垂直，才能真正的解决客户问题、创造价值、商业变现。

但这会撞上未来2-3年的一个主要矛盾： 历史上我们是通用工具厂商，我们的客户五花八门，客户的业务千奇百怪。**我们短时间能提供的标准品很窄 vs 客户想要的东西范围很广。**

# 应对策略

为了解决这个矛盾，搞两个事情，同步一下：

- 
**搞个“万能兜底”的平台（OEM合作）：**

准备找 hiagent 这种厂商 OEM 一个 Agent 搭建平台（低代码）。

- 
**目的：** 给前方销售一颗定心丸。客户提什么AI需求，我们都能先应承下来“能做”，有个万能接口能接得住。

- 
**建一支 FDE（前线部署工程师）特种兵：**

招募专门的 FDE 产品研发 进组。

- 
**目的：** 标准产品搞不定的，让人上去填。在非标准领域，帮客户做深度的定制化方案，用“人+工具”解决问题。

# 核心跨部门配合

**与 Luke（培训）这边的联动逻辑** 这两个动作能直接把培训盘活，而不只是讲课：

- 
**培训要有工具承接：**

以前培训完，客户虽然懂了AI，但没工具落地，跟帆软也没关系，等于“搞了个寂寞”。

- 
现在培训直接用我们 OEM 的平台做演练，学完就能上手用，跟我们产品强绑定。

- 
**培训是 FDE 的前哨：**

培训现场就是最好的需求挖掘场。

- 
**路径：** 培训脑暴场景 -> 现场用平台搭MVP（最小可行性产品） -> 筛选出有价值的大需求 -> 丢给 FDE 团队进场做深度实施。

# 风险与挑战

- OEM 的 Agent 平台必须与帆软的核心数据能力做底层打通。没有数据的 Agent 只是聊天机器人，有了帆软数据的 Agent 才是业务助理，这一点是连接帆软老产品的关键纽带。
- **FDE 的造血机制，**FDE 是高人力成本模式，如何避免变成纯外包？明确 FDE 的目标不仅是交付项目。
核心是为了做短中期的防守策略，缓解没有标品的尴尬，坚决杜绝以此为主航道做大做强的歪门邪道的想法。
- 其次是产品团队的“萃取模型”。该团队的 KPI 包含“将定制化需求转化为标准插件/模版/小工具”的指标。
- 最后为了避免被滥用，FDE 做的定制化项目，必须收取高额（50w起步）的咨询/实施费。
