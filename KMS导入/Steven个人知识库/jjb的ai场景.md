## 背景

过去半年，我们团队围绕"用 AI 降低销售日常工作的重复劳动、提升内容质量"这个目标，做了一系列实践。这些项目从日常写文档、复盘会议、管理机会、准备拜访，到完整的产品原型，覆盖了销售工作的多个核心环节。

以下按**可复制性从高到低**排列，前几个项目任何销售同学都可以快速上手。每个项目都附了核心工作逻辑和实际产出示例。
## 一、AI 自动生成内容并写入 KMS

**可复制性：★★★★★ ｜ 上手成本：低（需要 Claude Code + Confluence CLI）**
### 解决什么问题

销售同学日常要写大量文档——项目复盘、方案介绍、会议纪要、经验沉淀。写作耗时长，质量参差不齐，很多人有经验但"写不出来"。传统做法是用 AI 生成草稿再手动贴到 KMS，但复制粘贴、调格式、选父页面这些操作本身也是摩擦。
### 现在怎么做的

整条链路已经打通：**口述要点 → AI 生成 Confluence 格式内容 → 自动创建/更新 KMS 页面**，中间不需要手动复制粘贴。
### 技术路线

| | 交互入口 | Claude Code（命令行 AI 助手） | 在终端对话，直接说"帮我写一篇XXX发到KMS" | 
| 内容生成 | Claude（大模型） | 根据用户提供的要点，生成 Confluence Storage Format HTML | 
| KMS 写入 | Confluence CLI（命令行工具） | 自动调用 confluence create-child 或 confluence update，直接写入指定页面下 | 
| 格式控制 | Skill（预设指令模板） | 预定义页面结构、标题规范、标签体系，确保每次输出格式一致 | 

**关键点**：Confluence CLI 支持 Storage Format（Confluence 原生 HTML），所以 AI 生成的内容可以直接写入，表格、宏、页面内链接都能正确渲染，不需要手动调格式。
### 典型工作流示例

- 用户在终端说："帮我把今天和XX客户的会议要点写成 KMS 页面"
- AI 追问关键信息（或从录音文字稿自动提取）
- 生成 Confluence Storage Format HTML（含标题、表格、结构化内容）
- 调用 confluence create-child "页面标题" 父页面ID --file /tmp/content.html --format storage
- 返回页面链接，用户点开即可查看和微调

### 适用场景

- **项目/方案文档**：提供关键信息，AI 生成结构化文档并直接发布
- **会议纪要**：输入会议要点或录音文字稿，自动生成并写入 KMS
- **经验复盘**：口述或碎片化经验 → 条理清晰的 KMS 文章，一步到位
- **FAQ / 产品介绍页**：快速生成标准化说明页
- **批量内容迁移**：把分散在各处的文档统一整理后写入 KMS

### 实际效果

- 文档撰写 + 发布时间缩短 **50% 以上**（省掉了复制粘贴、调格式、选位置的时间）
- 输出内容结构更规范、格式统一
- 降低写作门槛——有想法就能沉淀，不用卡在"怎么写"和"怎么发"上

## 二、AI 辅助销售会议复盘

**可复制性：★★★★☆ ｜ 上手成本：需要录音转写工具**
### 解决什么问题

销售拜访结束后，复盘往往靠记忆和感觉。录音有了但没人有时间逐字听。有价值的行为细节和改进点被埋没在几十分钟的对话里。
### 怎么做的

- 会议录音转文字稿（飞书/讯飞等工具自动转写）
- 文字稿交给 AI，按预设的分析框架自动生成复盘报告
- 输出包括：会议概要、关键行为亮点、改进建议、客户信号解读
- 复盘报告自动发布到 Confluence，按人按时间沉淀

### 核心分析框架（脱敏版）

以下是 AI 分析销售会议时使用的 9 个维度，每个维度输出：评级（优秀/良好/待提升）+ 观察 + 原文佐证：
| | 1 | 倾听与主导比例 | 发言比例是否在 40%-50%，是否给客户足够表达空间 | 
| 2 | 需求挖掘质量 | 是否提出开放式问题、是否追问、是否总结确认客户需求 | 
| 3 | 异议处理方式 | 面对疑虑时是回避/强推，还是有效引导 | 
| 4 | 产品与技术知识 | 专业表达是否准确、能否将产品价值与客户场景连接 | 
| 5 | 推进与收口动作 | 是否设定下一步行动、是否在合适时机引导决策 | 
| 6 | 语言与表达习惯 | 口头禅、不确定性词汇（"可能""大概"）、表达清晰度 | 
| 7 | 情绪与压力应对 | 紧张时刻（沉默、质疑、价格压力）语言节奏是否受影响 | 
| 8 | 客户信号识别 | 预算暗示、决策权、紧迫度、竞品对比等关键信号是否被捕捉 | 
| 9 | 整体评分 | 1-10 分，用于跨会议趋势对比 | 

**评分硬性约束**：先统计"待提升"维度数 N，再限制分数上限（N≥4 → 上限4分；N=0且有"优秀" → 可达9-10分）。确保评分严格、跨会议可比。

**最终输出**：每次复盘还会提炼"本次最大亮点"和"如果重来"——选一个最关键的时刻，描述换一种处理方式会有什么不同。
### 累积行为画像

除了单次复盘报告，系统会维护一份持续更新的"行为画像"页面，按时间沉淀每次复盘的关键发现，用于看个人行为模式的长期变化趋势。
### 实际产出示例

- 我的销售行为画像 — 累积行为画像（持续更新）
- 销售复盘 - 2026-03-24 - 国药云 AI智能体医药营销场景落地与共创
- 销售复盘 - 2026-03-26 - 某制造业企业 AI驱动BI场景落地
- 销售复盘 - 2026-04-09 - 大全集团 AI赋能销售全流程

### 实际效果

- 一次 30 分钟的会议，原来复盘写 1 小时，现在**几分钟出完整报告**
- 分析颗粒度比人工复盘更细——能锚定到具体对话原文
- 按人持续沉淀，可以看到行为模式的变化趋势

## 三、AI 辅助职级答辩材料辅导

**可复制性：★★★★☆ ｜ 上手成本：需要了解公司答辩评审标准**
### 解决什么问题

答辩季，团队成员的材料质量直接影响通过率。作为管理者，常见的痛点是：

- 材料送到你手里已经快截止了，改都来不及改
- 你知道他有贡献，但他写不出来——你帮他改，又改不过来那么多人
- Peer review 协调成本高，反馈质量参差
- 同样的问题每年都在纠正：结构散、案例不聚焦、举证缺项、AI 味重

这套工具的定位是：**让 AI 承担"初审+结构化辅导"的工作量，把管理者从逐份改材料中释放出来**。
### 核心工作逻辑（脱敏版）

工具内置了评审逻辑，和评委看材料的路径一致：

**评委评审路径**：结果举证（底线）→ 关键行为（标准）→ 关键词（定位）

- **结果举证**：硬性门槛，每条都是打勾项，缺一项该能力不通过
- **关键行为**：评分标准，材料必须体现体系化运作、跨部门协同、赋能他人等行为模式
- **关键词**：定位锚点，所有叙述和案例围绕关键词展开

**AI 做的事**：

- **结构化诊断**：逆序检查——举证是否齐全 → 行为是否体现 → 是否围绕关键词。缺什么、弱什么，一目了然
- **材料重构**：按标准模板重写（要点式，评委扫一眼能抓关键信息），保留所有数据和证据，只改结构和表达
- **反 AI 味检查**：自动识别叙述性过渡段落、逐字稿式长段落、自我矮化表述等常见问题
- **问题预演**：模拟评审官可能提出的问题，帮候选人提前准备

**材料结构模板**（要点式，评委扫一眼能抓关键信息）：

- 关键词 / 关键行为 / 结果举证（照抄评审标准原文）
- 举证对照表（评审项 → 一句话举证映射）
- 案例：背景与难点（3-5句 + bullet 列核心矛盾）→ 关键动作（3-5条，粗体短标题 + 证据链接）→ 结果（bullet 列数据点）

### 对管理者的价值

- **批量提升材料底线**：团队成员自己过一遍 AI 初审，送到你手里的材料至少结构完整、举证不缺项
- **统一辅导口径**：不用每个人单独讲一遍"评委怎么看材料"，AI 已经内置了这套逻辑
- **释放你的精力**：你只需要看 AI 标出的问题和候选人的修改，做最终判断，而不是从头帮他改
- **减少答辩季的突击救火**：成员提前自查、自改，问题在早期暴露

## 四、AI 跟进日报自动总结

**可复制性：★★★★☆ ｜ 上手成本：需要 CRM 跟进日报数据源**
### 解决什么问题

管理者每天要看团队所有人的跟进日报，人一多、内容一长，根本看不过来。原始日报是流水账式的记录，哪些跟进有实质进展、哪些在原地踏步、谁今天工作量不够，全靠自己一条一条翻。
### 怎么做的

AI 自动读取每人当天的跟进日报，逐条分析后输出结构化摘要：

- **一句话总结**：每条跟进浓缩为一句话，抓住核心进展或问题
- **评分**：对每条跟进的质量打分（如 2 分 / 4 分），反映跟进深度和推进力度
- **工作量统计**：自动统计当天外出几次、电话几通，一眼看到工作投入
- **下一步动作**：提取或建议每条跟进的下一步行动

### 对管理者的价值

- **每天 2 分钟扫完全组**：不用翻原始日报，看总结就知道每个人今天干了什么
- **低分跟进一目了然**：评分低的跟进说明推进不力或停滞，可以针对性过问
- **工作量透明**：外出和电话数量直接统计，不需要另外统计考勤
- **下一步可追踪**：每条跟进都有明确的下一步，下次可以对照检查是否执行

## 五、AI 辅助销售机会管理

**可复制性：★★★☆☆ ｜ 上手成本：需要建立团队填报机制**
### 解决什么问题

组长怎么持续看见团队最重要的机会，并在对的时候给到支持？过去靠口头汇报，口径不统一、信息散、风险机会不一定浮上来。
### 机制设计

围绕"每人每周填 5 个重点机会"建立结构化沉淀。这里"5 个重点机会"本质是**承诺机制**——在表上的机会有资源支持（组长精力、协调售前等），不在表上的没有。用"管理资源分配"驱动填写行为，而非靠系统强制。
### Agent 做了什么

**1. 填报流程自动化**

- 每周二早上自动创建当周空白模板（Confluence 页面，每人一张表、5 行空白行）
- 周六/周日分四轮自动检测填写状态，只@未填写的人

**2. 深度分析（当前 v4）**

分析能力已迭代四版，从基础规则到 MEDDIC 框架深度诊断：
| | MEDDIC 六维扫描 | Metrics / Economic Buyer / Decision Criteria / Decision Process / Identify Pain / Champion，每维度 0-2 分 | 
| 7 类隐性风险检测 | 预算风险、决策链断裂、虚假紧迫感、竞品暗涌、Champion 动摇、需求膨胀、关键人恐惧点 | 
| 跨周待办追踪 | 自动对比上周"下周关键动作"的完成情况（completed / pending / overdue / new） | 
| 跨周异常检测 | 消失机会、停滞机会、健康度突变、预测时间过期 | 
| 智能凭证路由 | 商务记录 → MEDDIC 全套分析；图片凭证 → Vision API 解读；无凭证 → 规则引擎兜底 | 

分析结果以诊断卡片形式追加到 Confluence 页面，组长打开就能直接看。
### 实际产出示例

- 苏皖销售二组-2026-W14机会周报 — 含填报内容 + AI 诊断卡片

### 目前能看到的价值

- 分散口头信息收进统一页面，沟通成本更低
- Agent 把需要注意的点先抬出来，组长不用从零翻内容
- 凭证字段 + MEDDIC 引用原文判断，"只写漂亮话"变难了
- 跨周对比开始发挥作用：消失/停滞/健康度突变不再只靠人记
- 催报自动化释放管理精力

### 坦诚说还没解决的问题

- 分析质量受填写质量制约——填得模糊，分析也薄
- 图片凭证处理稳定性还不够，文本凭证效果更好
- 数据积累还需时间，真正有价值的趋势判断需要更长周期

## 六、AI 辅助客户拜访准备

**可复制性：★★★☆☆ ｜ 上手成本：需要沉淀产品知识库**
### 解决什么问题

拜访前准备方案耗时长，尤其是新客户——要查背景、想场景、匹配产品、准备演示材料。经常因为时间紧导致准备不充分。
### 核心工作逻辑（脱敏版）

- **收集信息**：确认客户名称 + 需求描述（一句话即可）
- **读取知识库**：按行业快查表 → 行业痛点文件 → 对应产品文件 → 客户历史文件的顺序读取
- **搜索客户背景**：自动搜索公司简介、主营业务、规模，整理 2-3 条客户专属痛点
- **输出大纲**（30 分钟演讲结构）：封面 → "我们了解您"（3个关键事实）→ 今天的挑战（角色化痛点）→ 产品全景 → 重点场景演示 → 建议下一步
- **生成 HTML 演示材料**：场景卡片必须包含：角色化痛点 + 具体演示步骤（有人物、有界面、有输入输出）+ 量化指标

### 实际效果

- 拜访准备时间从 **2-3 小时缩短到 30 分钟内**
- 方案针对性更强——基于客户实际业务场景，而非通用模板
- 降低新人准备拜访的门槛

## 七、AI 产品演示教练

**可复制性：★★★☆☆ ｜ 上手成本：需要沉淀产品知识库 + 异议应对库**
### 解决什么问题

产品演示是销售最核心的现场动作，但质量参差很大。常见问题：上来就讲功能清单、Demo 没有场景感、客户质疑时慌了、不知道什么该讲什么不该讲。尤其新产品（AI 产品线），很多人自己都还没讲明白。
### 核心工作逻辑（脱敏版）

内置了一套从实战录音中提炼的**"六步演示法"**，AI 根据产品+客户场景，生成一份销售可以直接拿去讲的演示脚本：
| | **1. 认知拉通** | 在讲产品之前，先把客户认知拉到同一水平线 | 先破后立：先承认过去的问题，再讲现在的升级 | 
| **2. 进化叙事** | 讲产品演进故事，建立成熟度信任 | 主动暴露过去的问题，客户反而更信任你 | 
| **3. 架构白盒** | 用透明方式讲技术架构，区别于竞品黑盒 | 讲架构不是秀技术，是建立信任 | 
| **4. 场景 Demo** | Demo 的主角是客户的场景，不是你的功能 | 让客户参与互动，体感远强于你自己演示 | 
| **5. 价值锚定** | 用业务语言总结，给客户一句"能回去跟老板汇报的话" | 量化 > 定性，有数字永远比"效果很好"有说服力 | 
| **6. 诚实边界** | 主动说清楚能做什么、不能做什么 | 主动说"不行"比被动被发现"不行"好一万倍 | 

### 输出内容

一份完整的 Markdown 演示脚本，包含：

- **每个步骤的参考话术**（口语化，可以直接讲，不是念的）
- **Demo 演示动线**（先演示最有共鸣的场景 → 再演示差异化能力 → 最后演示扩展性）
- **Top 3 异议预判 + 标准应对话术**（从异议应对知识库匹配）
- **速查卡片**：一句话定位、核心差异化、最强金句、最佳 Demo 场景、绝对不要说

根据客户决策角色自动调整深度：IT 负责人讲深架构，业务负责人讲场景和效果，CEO 只讲价值和案例。
### 演示铁律（六条）

- 先认知后产品——客户认知没到位，产品讲得再好也是对牛弹琴
- 先痛点后方案——不要上来就讲"我有什么"，先讲"你缺什么"
- 先场景后功能——功能是手段，场景是目的
- 先承认后解决——遇到历史问题或竞品质疑，先承认再讲解决方案
- 先价值后价格——永远在客户认可价值后再谈商务
- 宁可少讲也不要乱讲——讲三个点讲透，比讲十个点都浮皮潦草好得多

## 八、6 周 AI 实战训练营（团队能力建设）

**可复制性：★★★☆☆ ｜ 上手成本：需要有人持续带**
### 解决什么问题

销售团队需要理解 AI 才能更好地向客户传递产品价值，但"培训 AI"不能只是听课——得动手做出东西来。
### 怎么做的

为团队（3-5 人，无编程背景）设计了 6 周实战培训，核心原则：**每周出一个能跑的东西**。
| | W1 | 给 Confluence 工具加一层 | Claude Code | 理解多步骤链式调用 | 
| W2 | 让 AI 同时用多个工具 | Corevo | 理解 ReAct 架构、Tool 协同 | 
| W3 | 同一个任务两种做法 | 扣子（Coze） | Workflow vs Agent 的选择 | 
| W4 | 做一个有界面的 AI 应用 | Trae | 前后端架构、部署 | 
| W5 | 给真实客户设计 AI 方案 | 自选 | 架构选型、方案设计 | 
| W6 | 路演答辩 | 自选 | 能做 → 能讲清楚 | 

### 设计理念

架构知识不是"先看再做"，而是**"做的过程中卡住了 → 给一张概念卡 → 看完就能突破"**。这才是成年人学习的方式。销售团队学 AI 的动力来源不是"老板让我学"，而是"我做出了一个东西，客户/同事觉得牛"。
## 九、声迹 SalesTrace — 黑客马拉松参赛项目

**项目状态**：Demo 已完成，即将参加黑客马拉松
### 一句话定位

**帮销售主管用 AI 高效辅导每一个人。**
### 要解决的问题

传统销售管理工具的致命问题：**销售觉得自己被监控**。一旦产生这种感受，填报就变成应付，数据失真，系统沦为摆设。
### 声迹的解法

| | **销售** | 渴望被认可，想知道自己哪里做得好 | 正向激励为主（80% 鼓励 + 20% 建议），提交即获得有代入感的成长反馈 | 
| **主管** | 渴望高效辅导，想针对性带人 | 客观洞察 + 可操作的辅导建议，不需要逐个听录音 | 

### 核心飞轮

销售自愿提交对话 → 主管获得辅导素材 → 基于洞察做真实辅导 → 销售感受到价值 → 持续提交
### 产品亮点

- **辅导台，不是考核台** — 展示"谁最值得关注"，不展示"谁最差"。同样的数据，不同的叙事
- **地域风格体系** — 用省份命名销售风格原型（"上海之镜·精致专业型""四川之韵·关系亲和型"等），基于沟通力、共情力、逻辑力、控场力、专业度、提问力、推进力 7 个能力维度映射，既有专业分析又有社交传播性
- **AI 是注意力分配器** — 所有结论锚定对话原话，建议具体到"下次可以说什么"，不说空话

### 技术实现

- **技术栈**：React + Node.js + SQLite + Claude API
- **开发方式**：非开发背景，全程用 AI 辅助编码（Claude Code），从零搭建完整 Web 应用
- **这本身就是一个 AI 提效的案例**：一个销售用 AI 工具做出了一个完整产品原型

## 写在最后

以上项目的共同思路是：**不追求技术复杂度，追求真实场景下的效率提升**。AI 工具的门槛已经足够低，关键是找到自己工作中重复、耗时、有模式可循的环节，让 AI 来承担。
