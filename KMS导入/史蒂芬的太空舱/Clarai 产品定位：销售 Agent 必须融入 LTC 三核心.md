# Clarai 产品定位：销售 Agent 必须融入 LTC 三核心

核心判断：Clarai 不能独立于 CRM 和流程之外。销售最核心的就是三件事——线索、机会、回款。Clarai 应该思考怎么融进这三个部分，而不是上来干十几个场景。

## 一、一个危险的叙事

市面上很多 AI 销售助手都在讲一个故事：**CRM 是旧时代的产物，AI Agent 会取代它**。

"CRM 会被压缩成一个数据库，GUI 会消失，销售只需要跟 AI 对话。"

这个叙事很性感，但我要说：**客户的 CRM 不会被压缩成数据库**。

除非 Clarai 的流程机制非常完备——内置完整的流程引擎、责任主体定义、KCP 指标追踪。做到这些，Clarai 就不是"销售助手"，而是 AI-Native CRM，一个全新的产品。这需要巨大的工程投入，不是短期内能完成的。

更现实的判断：**CRM 正在被重新定义，而不是被取代**。

## 二、帆软自己的 CRM 已经被压缩成一线作业平台

帆软的 CRM，现在承载的是几十道工序：

- 商务录入

- 操作合同

- 产品功能配置

- 合同处理

它不是"记录系统"，而是**作业执行平台**。每一道工序都有明确的输入输出、责任主体、流程节点。

这给了我们一个启示：**CRM 的价值在于承载流程，而不是存储数据**。

如果 Clarai 要"取代 CRM"，它必须能承载这些工序——不是"AI 自由发挥"，而是"AI 按流程执行"。这需要：

- 流程引擎（谁负责？什么时候做？怎么做？）

- 责任追踪（KCP 指标：验证应期达标率、机会预测准确率、回款及时率）

- 可视化界面（管理者需要看到战场地图）

做不到这些，Clarai 就只能是"边缘工具"，而不是"核心系统"。

## 三、LTC 三核心：线索、机会、回款

帆软三年 LTC 流程变革，核心始终围绕三件事：

| 
| **核心模块** | **管理对象** | **关键动作** | **KCP 指标** | 

| --------- | --------- | --------- | --------- | 

| **管理线索** | **线索分级验证** | **电话邀约、拜访跟进** | **线索验证应期达标率 82%** | 

| **管理机会** | **机会预测推进** | **周例会盘点、权力地图** | **机会预测准确率 50%** | 

| **管理应收** | **回款责任落实** | **催收流程、理应回款时间** | **回款及时率 70%+** | 

这三件事，构成了销售的**价值流动闭环**：

任何销售 AI 产品，如果不能嵌入这个闭环，就只是在做"边缘优化"——减少一些 paperwork，生成一些报表，但无法触及销售的核心价值创造。

**Clarai 应该思考怎么融进这三个部分，而不是上来干十几个场景。**

## 四、两种融入路径

### 路径一：融入销售管理平台（LTC）——简单路径

销售易、纷享销客都有类似的管理平台——看板、报表、例会支撑。Clarai 可以作为"智能层"嵌入：

**切入点：销售周会提效**

帆软 LTC 二阶段找到的关键洞察：

回到最高频的管理场景，协助开好每一场小组业务周例会。

战区年访问量 15 万次，600 人人均 250 次。这是最高频的管理场景。

Clarai 可以：

- 会前：自动生成周报摘要，检出异常波动（已实现 100%检出率）

- 会中：实时数据查询，机会推进建议，待办创建

- 会后：待办追踪，下周预测校准

这条路径的优势：**管理场景天然结构化，数据质量高，AI 容易产生价值**。帆软已验证——200+ 覆盖销售及 CS，60-70% 活跃用户留存。

### 路径二：融入作业管理平台——难度高一点的路径

帆软的一线作业平台，承载几十道工序。Clarai 要融入这里，不能"泛泛地做销售助理"，而是要**从几十道工序里挑几个重点的 Agent**：

| 
| **工序** | **Agent 化可能性** | **价值判断** | 

| ----- | --------------- | --------- | 

| 商务录入 | 高（跟进记录 Agent 已验证） | 减少 90% paperwork，100% 数据沉淀 | 

| 合同操作 | 中（AI 合同审核已验证） | 商务条款风险识别，利润率预警 | 

| 产品功能配置 | 低 | 需要专业判断，AI 辅助但难替代 | 

| 合同处理 | 中 | 流程型工序，可自动化推进 | 

关键判断：**不是所有工序都适合 Agent 化**。要选择那些"高频、重复、结构化"的工序。

## 五、GUI 短期不会消失

销售管理需要"看见"。

帆软 LTC 三级联动作战体系：

- **班长的战争**：小组业务综合看板（线索、行程、机会、应收）

- **团长的战争**：区域/BU 经营视角（绩效赛马、业绩预测、战略专项）

- **军长的战争**：CEO/BG 总裁视角（战略执行、预算情况、风险透明）

每一层都需要**数据驾驶舱**，不是 AI 对话。

AI 可以生成报表、检出异常、提供建议，但**决策需要可视化呈现**。管理者需要一眼看到问题在哪里、差距有多大、谁在拖后腿。

GUI 不是"旧时代的包袱"，而是**决策效率的必需品**。

## 六、销售管理的 AI 化：依托周会提效

帆软 LTC 的核心经验：

流程建设必须从业务中来到业务中去。

Clarai 的产品定位，也应该遵循这个原则。

**销售管理，可能依托于"AI-销售周会提效"这个点。**

这不是"泛泛的销售助手"，而是：

- 嵌入最高频的管理场景

- 在具体场景中验证价值

- 逐步扩展能力边界

从周会提效开始，再扩展到：

- 经营复盘 Agent（1 分钟生成报表，70% 管理复盘提效）

- 机会预测校准（准确率从 20% 到 40% 且稳定）

- 应收管理预警（及时率从 50% 站上 70%）

## 七、Clarai 的产品定位

基于以上判断，Clarai 的产品定位应该是：

| 
| **判断** | **定位** | 

| ----- | ----- | 

| **不是"独立的销售助手"** | **而是"嵌入 LTC 流程的智能层"** | 

| **不是"取代 CRM"** | **而是"让 CRM 从记录系统变成作战系统"** | 

| **不是"做十几个场景"** | **而是"聚焦线索、机会、回款三核心"** | 

落地路径：

| 
| **阶段** | **目标** | **关键场景** | 

| ----- | ----- | --------- | 

| **第一阶段** | **融入销售管理平台（LTC）** | **销售周会提效、经营复盘 Agent** | 

| **第二阶段** | **融入作业管理平台** | **跟进记录 Agent、合同审核 Agent（从几十道工序里挑重点）** | 

| **第三阶段** | **扩展能力边界** | **客户洞察 Agent、打单教练 Agent** | 

每个阶段都要**在具体场景中验证价值**，而不是"先建平台再找场景"。

## 八、最后的话

**客户的 CRM 不会被压缩成数据库**，除非 Clarai 的流程机制非常完备。

**帆软自己的 CRM 已经被压缩成一线作业平台**，承载几十道工序——这是 CRM 的未来形态。

**Clarai 应该融入销售管理平台 LTC**，以销售周会提效为切入点——这是简单路径。

**难度高一点的是融入作业管理平台**，从几十道工序里挑几个重点 Agent——这是深度路径。

**销售最核心的就是三件事：线索、机会、回款**。Clarai 应该思考怎么融进这三个部分，而不是上来干十几个场景。

不是"拿着锤子找钉子"，而是"精准打击"。
