# 2026-03-26

#AI时代小记 企业级智能体的三种形态

* * *

## 核心判断

金蝶现在推的智能体像"固定解题模板"，题一变就得定制。企业级智能体未来应该是三种形态。

## 三种形态

形态定位成熟度金蝶现状一非结构化知识库智能体最成熟、最容易出成果有支持，可先推二结构化数据分析智能体可通用，但需BI引擎底座太碎片化、固化，缺自有BI引擎三任务智能体（调用Skills）可发挥金蝶本体优势应重点挖掘

## 形态一：知识库智能体

- 对接任意知识库，实现知识共享
- 技术最成熟，容易出成果
- **建议**：可以先推一推

## 形态二：数据分析智能体

- 理想状态：通用智能体，对接任意数据进行洞察分析
- 金蝶现状：
  - 没有自己的BI引擎作为基础能力
  - 推出的智能体（带资料、毛利、财务分析等）太碎片化、太固化
  - 个性化成本高，实用性不强
  - ChatBI 只能问简单问题，用处不大
- **结论**：金蝶在这一块任重道远

## 形态三：任务智能体（重点）

- 直接调用任意 Skills 完成特定任务
- **应重点挖掘的场景**：客户想"少点几次鼠标"的操作

  - 订单自动同步
  - 物流拍照自动录单
  - ……
- 这些才是客户觉得值的功能

### 商业模式转型

- 冲击：按用户数收费的老模式会被冲击
- 新思路：
  - 金蝶厂商：学习大模型厂商收 token 费用 → 改收 **API 调用费用**
  - 金蝶伙伴：收 **开发 Skills** 和 **智能体增值服务** 费用

## 最终判断

- AI 会减少大量人工操作，但 ERP 里的表单和流程不会消失（因为要合规）
- **金蝶要做**：赶紧完善 API 和 Skill 生态
- **伙伴要做**：赶紧做好相应准备

* * *

【以下为原文】

现在金蝶推的这些智能体像不像给了客户几个固定的解题模板。题稍微一变就得定制。费时费力还不一定好用。

在我看来，企业级的智能体未来就是三种形态。第一，非结构化的知识库，智能体能对接任意知识库，实现知识共享。第二，结构化的数据分析，智能体，实现智能问数，数据洞察输出报告。第三，小龙虾这种任务智能体可直接调用任意 skills 完成特定的任务。

那第一种技术呢，最成熟也最容易出成果，金蝶也有支持智能体，这个可以先推一推。那第二种结构化数据本来是可以做成一个通用的智能体对接，任意数据都可以进行洞察分析的，但因为金蝶没有自己的 BI 引擎作为基础能力，所以现在推出的几个智能体，比如带资料，毛利，财务分析等等，做的都太碎片化。也太固化，那个性化的成本就会比较高，并且实用性也不强。而 chat BI 呢，又只能问一些简单的问题，用处不大，金蝶在这一块任重道远。

第三种呢，则是可以真正发挥金蝶本体优势的，要重点挖掘客户，想少点几次鼠标的这种场景，把它变成金蝶的 skills。比如订单，自动同步，物流拍照，自动录单等，那这些才是客户觉得值的功能。虽然这样会冲击按用户数收费的老模式，但对金蝶厂商来说呢，可以学习大模型厂商人家收 token 费用你就收 API 调用费用，对于金蝶伙伴来说就收开发 skills。和或者呢智能体的这个增值服务费用。

那 AI 未来肯定会大量减少人工操作，但 ERP 里的表单和流程不会消失，因为要合规。所以金蝶要做的是赶紧完善 API 和 skill 生态，对于金蝶伙伴也要赶紧做好相应的准备。
