#AI时代小记 飞书 CLI 开源，GUI 时代的终结

* * *

## 核心判断

飞书开源 CLI 不是技术新闻，而是一个信号：GUI 正在被 CLI 反向吞噬，而这次的新用户是 AI Agent。

## 一、发生了什么：GUI 与 CLI 的反向互换

- **历史**：计算机从 CLI（命令行）开始 → GUI（图形界面） democratized 电脑使用
- **现在**：GUI 正在被蚕食，新用户不是人，是 AI Agent
- **CLI 优势**：天然适合被 AI 操控，AI 的核心交互是文字/指令/代码，CLI 就是用命令操作一切
- **体验分水岭**：过去软件面向人类视觉（看到按钮才相信），现在面向 AI 逻辑（一个接口，AI 来调用）

## 二、飞书为什么激进：三级跳战略

1. **2月**：接入 OpenClaw 插件
2. **3月中**：上线 AI 智能体平台 aily
3. **3月底**：全量开源 CLI（2500+ API，覆盖消息/文档/日历/多维表格）

**战略逻辑**：我开放得越彻底，就越没有人能绕过我

## 三、飞书看清的三件事

#判断含义1平台价值指标被改写DAU/停留时长/点击率 → Agent 调用频次、自动化完成度2真实资产是上下文谁跟谁什么关系、什么会议、哪些文档关联、权限怎么设置——All-in-One 的上下文厚度是 Agent 生产力的前提3AI 不会只在一个平台活动最终同时养着 Claude Code/Cursor/自建助手，飞书若固守 GUI 领地，只会被工作流绕过

## 四、飞书 vs 钉钉：两条相反的路

维度飞书钉钉**核心赌法**最开放的平台赢家生态协同能力最强的平台赢家**开放策略**全量开源 CLI + 多入口（开发者/普通员工/第三方插件）只开放高频通用场景 CLI，核心能力在内部"悟空"中枢流转**调度方式**Agent 自由拼装调用钉钉自己的"悟空"统一编排淘宝/支付宝/阿里云等生态能力**风险**可能被超级 Agent 绕过若生态协同不够强，Agent 会找更开放的入口

## 五、对软件设计的根本颠覆

- 过去：设计面向人类的视觉，需要看到按钮
- 现在：设计面向 AI 的逻辑，只需要接口
- 结果：用户可能永远打不开你的界面，但 Agent 在后台完成了全部流程

【以下为原文】

飞书在3月28日开源了CLI（命令行工具），支持调用2500多个API，覆盖消息、文档、日历、多维表格等全部核心功能。这个消息本身看起来很技术。但如果你真的用Claude Code或任何其他AI编程助手试过，就会发现一个转变：你不再需要打开飞书界面了。

# 1\. 安装CLI

npm install -g @larksuite/cli

# 2\. 安装全部Skills

npx skills add larksuite/cli -y -g

# 3\. 初始化配置（会生成授权链接）

lark-cli config init --new

# 4\. 登录（推荐权限一键授权）

lark-cli auth login --recommend

# 5\. 验证

lark-cli auth status

扫码授权后，重启Claude Code，飞书的19个Skill就会出现在工具列表里

一句话，AI就在后台完成了你曾经"打开飞书-找到文档-编辑-保存"的整个流程。这对使用者来说是解放，但对传统的软件设计逻辑来说，是一场根本的颠覆。

这背后发生了什么？

GUI和CLI的反向互换

计算机的历史其实是从CLI开始的，那些黑乎乎的屏幕，敲一行命令，吐一行结果。后来有了Windows、Mac的图形界面，普通人才开上电脑。GUI的出现是民主化，让非技术人群可以直观地操作软件。

现在这个过程反过来了。GUI正在被蚕食，但这一次的"新用户"不是人，是AI Agent。

CLI有一个GUI永远做不到的优势：它天然适合被AI操控。AI最核心的交互方式依然是文字，是指令，是代码命令。CLI恰好就是用命令来操作一切的。你告诉Claude Code"把我飞书日程里这周的会议整理成一份markdown文档"，AI不需要看界面、找按钮、点点点，它直接执行一行命令，调用飞书的API，几秒钟就搞定了。

这是一个体验层面的分水岭。过去软件的设计是面向人类的视觉，我们需要看到按钮才能相信它存在。现在软件的设计开始面向AI的逻辑，只需要一个接口，告诉AI能做什么，AI就来调用。

飞书为什么这么激进？

飞书走这一步不是被逼的。它看清了一件事。

首先，衡量一个平台价值的指标正在被悄悄改写。过去十年，企业应用关注的是DAU、用户停留时长、点击率。但如果所有的操作都被AI代理了，用户根本打不开这些平台的界面，这些指标反而会下降。飞书做出的判断是：与其守着逐渐贬值的数字，不如主动拥抱新的衡量标准，Agent调用频次、自动化完成度。

其次，飞书沉淀的真实资产不是功能，而是上下文。企业在飞书里堆积的是完整的工作背景，谁跟谁有什么关系、什么时间有什么会议、哪些文档关联到哪些项目、权限体系怎么设置。这种All-in-One平台带来的上下文厚度，是智能体产生真实生产力的前提。当Agent进来调用得越多，这套上下文资产的价值就被放大得越高。它不怕开放，因为开放出去的东西本质上是为了让更多的Agent进来依赖飞书。

第三，飞书看清了一个趋势：AI不会只在飞书里活动。我们最终会同时养着Claude Code、Cursor、或者某个自建的AI助手。这些Agent需要协调多个平台的数据，一会儿查飞书的日程，一会儿要从GitHub拉代码，一会儿需要发邮件。如果飞书此刻还在固守自己的"GUI领地"，最终的结果就是被Agent的工作流绕过。

所以你会看到飞书在一个月内完成了"三级跳"：2月接入OpenClaw插件，3月中上线自己的AI智能体平台aily，3月底全量开源CLI。每一层都不绑定，每一类用户都有入口，开发者用CLI构建完全自定义的Agent，普通员工直接用aily，已经养龙虾的用户通过官方插件接入。但所有入口都在调用同一套底层能力。

这是一个非常清晰的战略：我开放得越彻底，就越没有人能绕过我。

钉钉为什么选择相反的路？

钉钉也在做开放，但方向完全不同。钉钉用了一年多时间重写底层代码，把所有产品能力拆解成AI可以直接调用的系统指令。然后搭建了一个叫"悟空"的统一调度入口，这是钉钉自己的AI中枢，负责协调淘宝、支付宝、阿里云等生态内外的能力。指令在悟空这里统一编排，然后下达到各个系统，整个过程直接发生在系统层面，中间没有转译层的延迟。

同时，钉钉对外开放的CLI，只包括日历、待办、DING消息这些高频通用场景。涉及商业流程的核心能力、生态间的深度协同，统统只在悟空内部流转。

这两个企业平台的选择截然相反，说明了不同的产业判断：

飞书赌的是，最终赢家是最开放的那个平台。越开放就越有吸引力，越多的Agent会主动选择你。

钉钉赌的是，最终赢家是生态协同能力最强的那个平台。它不信任Agent的自由拼装，坚持由自己的悟空来做统一编排。因为它的核心竞争力，历来不是某一个工具，而是贯通电商、支付、云服务的全链路商业能力。

两条路都有逻辑。飞书的风险是可能被绕过，如果某个超级Agent太聪明，用户可能直接跳过飞书去调底层API；钉钉的风险是如果生态协同不够强，Agent可能会找更开放的入口。但最终，这两条路都在指向同一个方向：平台的价值不再取决于人花多少时间在界面上，而取决于Agent能不能高效地调用平台背后的数据和上下文。
